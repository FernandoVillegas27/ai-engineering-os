# Dependency-Aware Multi-Agent Scheduler

## Purpose

P8 introduces the deterministic task scheduler that coordinates when specialist agents may work.

The scheduler does not choose models and does not reason about implementation details.

Its job is to turn a validated task DAG into reproducible execution readiness.

## Task graph

Each task contains:

- stable task ID;
- assigned agent;
- dependencies;
- whether it mutates project files;
- authorized file scopes;
- lifecycle status.

The graph must be acyclic.

Unknown dependencies and self-dependencies are rejected.

## States

Initial scheduler states:

- `queued`
- `ready`
- `running`
- `waiting`
- `blocked`
- `completed`
- `failed`
- `cancelled`

Readiness is derived from dependency state.

## Deterministic ready queue

Ready tasks are ordered by stable task ID.

`AcquireReady(limit)` selects up to the requested concurrency limit and marks those tasks running.

This makes scheduling reproducible for the same graph and state.

## Dependency propagation

A task becomes ready only when all dependencies completed successfully.

If a dependency fails, is blocked or is cancelled, dependent work becomes blocked.

Independent branches remain eligible to continue.

## Mutating file scopes

Parallel mutation is allowed only when file scopes do not overlap.

Scopes are normalized repository-relative paths.

Examples:

~~~text
backend/api
frontend
migrations
~~~

Wildcards and traversal scopes are rejected in the initial scheduler.

Two scopes conflict when they are equal or when one contains the other.

Example:

~~~text
backend
backend/api
~~~

conflict.

Read-only/non-mutating tasks do not take file-scope locks.

## Cancellation

Individual tasks can be cancelled before terminal completion.

Dependency cancellation blocks downstream tasks.

`CancelAll` provides run-level cancellation propagation for all non-terminal tasks.

## Progress

Progress is derived from scheduler state rather than generated by a model.

The scheduler exposes counts for every task state.

A later Control Plane can calculate user-facing progress and critical-path information from this graph.

## Current boundary

P8 provides deterministic graph/state scheduling.

It does not yet:

- invoke runtimes;
- persist scheduler transitions as events;
- route messages automatically;
- merge isolated mutating workspaces;
- dynamically replan the graph.

Those responsibilities belong to Orchestrator v2, the event/control plane, and merge coordination phases.
